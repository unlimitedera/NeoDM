# Bundled source investigation for 1.8.0

The initial investigation below is preserved as a historical snapshot. Its Gyan source blocker was resolved by adopting the verified TAS-FFMPEG replacement, not by assigning unrelated source to the old binary. The native curl dependency closure was subsequently retrieved and its DLL byte-matched to the one embedded in yt-dlp. Deno now has a reconstructed notice/source superset from the exact release Cargo.lock and source asset. See `BUNDLE-VERIFICATION.md` and `tools/bundled-source.lock.json` for the final material inventory, exact hashes and review boundaries. The redistribution gate still verifies actual material and has no bypass.

## Verified alternative candidate

A later targeted search found the `NevermindNilas/TAS-FFMPEG` v9.0.2 release. Its official API lists a corresponding-source asset and a Windows shared build. Both were downloaded and their SHA-256 values match the GitHub asset digests:

- `tas-win64.zip`, 35,544,612 bytes, SHA-256 `148dfe8595ebf10a217d7e56fef732bcb2fabd3e33dfc4a37accf76f864ba19b`.
- `tas-corresponding-source.tar.xz`, 374,513,656 bytes, SHA-256 `539994be99dfbe0a6aa4d56f4d6d024dee92f655f146172d1935177377b0b1ee`.

`tas-release.json`, `tas-win-entries.json` and `tas-source-entries.json` retain the API response and archive inventories. The source archive contains 30,339 entries including dependency source trees, build scripts, flags, a versions lock and build environment definitions. This is a concrete candidate for replacing the current ffmpeg bundle, not evidence that the Gyan executable is covered. The Windows ZIP uses multiple shared DLLs. Adopting it requires reviewing its source closure, pinning and verifying all runtime DLLs as well as the executable, updating the provisioning gate and rerunning media/security/installer verification. No production pin was changed to an unaudited alternative. The exact yt-dlp and Deno requirements below also remain open.

## Exact remaining requirements

1. Collect complete corresponding source and applicable notices for the standalone yt-dlp executable, including its packaged Python runtime, native dependencies, EJS and build tooling. Match the one-file binary to build evidence rather than assuming dependency declarations are its complete inventory.
2. Obtain the ffmpeg publisher's exact build and patch scripts and source for every linked dependency. The README gives many codec-library revisions, but not exact versions for supporting libraries including fontconfig, iconv, GnuTLS and its dependencies, GMP, bzip2, LZMA, zlib and libxml2. Do not fill these gaps with current upstream versions. A controlled replacement build with retained inputs is an alternative.
3. Collect applicable Deno third-party license and copyright notices for this exact release. The root MIT text alone is insufficient evidence.
4. Build a real source release asset with its manifest and deterministic hashes, and ship accurate license and source-access instructions with the binaries. Make source available from the same release. An About credit, homepage or unsupported written offer does not satisfy the gate.

No `tools/bundled-source.lock.json` was fabricated. Existing checks remain active. A working helper executable is not redistribution approval. The ordinary build can pass independently of the installer gate. See `BUNDLE-VERIFICATION.md` for the manifest contract and build commands.
