# Link grabber and custom categories (1.9.0)

## Link grabber

Open it from Tasks > Link grabber, the sidebar button, Ctrl+Shift+V (with the text on the clipboard) or the buttons of the empty download list. You can also drop text, links or a list file (`.txt`, `.csv`, `.m3u`, `.m3u8`, `.json`, `.lst`, `.list`, `.url`, `.html`, `.md`, `.log`, up to 4 MB each) on the main window. A dropped `.torrent` file is added as a torrent instead.

What it does:

1. **Find links.** Any text is searched for `http` and `https` links. Other schemes (ftp, file, magnet, javascript, data, mailto), links with a user name or password, links without a host and links longer than 8192 characters are ignored and counted. Repeats (also when only the `#fragment` differs) are skipped. At most 5000 links are kept and at most 8 million characters of text are read. Trailing punctuation is dropped, and a closing bracket stays only when the link itself holds the opening one.
2. **Stage them.** The table shows a tick box, the file name (guessed from the address, editable), the site, the size and a status. Nothing downloads from here. Links that are already in your downloads start unticked, YouTube links are not offered (use Add URL for the quality choices). The filter box matches name, site, address and extension; the site box limits the table to one host.
3. **Check links (optional).** Asks each site with HEAD, and a one byte ranged GET when HEAD is refused, using the same proxy, identity, referer and compatibility steps as a download. At most four checks run at once, the pass can be stopped, a link that looks single use (a long address with a token-like path part) and stream playlists are never requested. 404 and 410 mean "Not found" and untick the row, a web page answer is flagged "Web page, not a file", every other failure is "Unknown". A name the server gives replaces the guess unless you typed one.
4. **Package and folder.** A package name groups the downloads (shown in the Package column, found by the search box). The files go by the category rules, into a folder you choose, or into a new folder named after the package under the download folder or the chosen folder. The package folder name is made safe like any file name.
5. **Add.** Add to queue starts the downloads in table order within the connection limit of Options > Downloads. Add paused adds them waiting. Duplicates and failures are reported, and the queue is saved once for the whole batch.

What it does not do, by design: it does not read web pages for hidden links, it has no per-site plugins, it does not solve puzzles, skip waiting times or use accounts. A link that returns a web page instead of a file fails with the usual wrong-content message.

### Packages and page links (1.16.0)

**Packages.** When two or more ticked links are clearly the parts of one set (same site, same name, different part numbers: `Part_1.zip` to `Part_4.zip`, `name.part1.rar`, `name.zip` with `name.z01`, `name.001`, `name (1 of 4).zip`, `name_01.zip`), the package name box is filled with the shared name (or "Files from the site" when the names are only Part_N), the queue box offers a new queue of that name, and "Start automatically" is ticked. "Add and start" then adds the links to that queue and starts it. Untick it to add them paused. A name you typed is never replaced. One numbered file alone is not a set. If several sets are ticked at once, tick one set at a time to give each its own package.

**Page links.** Some file hosts answer a link with a web page (a timer, a button) and not the file. Before a package is added, NeoDM looks at up to 40 ticked links that were not checked yet (a short request, at most about 20 seconds in total) and marks the ones that answer with a page. Those are added paused and resolved in the NeoDM browser:

1. one link at a time, in the order of the table, in one small window that does not take the focus;
2. NeoDM loads the page, waits for the page's own countdown and clicks the one control whose own text says Download, Free download, Slow download, Create download link, Get link or Continue. Controls that say Premium, Buy, Upgrade, VIP, Fast, Install or similar are never clicked. A control that is still disabled or hidden means the timer is still running: NeoDM waits and does not click;
3. the download that the click starts is cancelled in the browser and given to the same download in the package (address, name, the cookies the browser holds for that address only, user agent and the page address as referrer), and the download continues in its queue with those details, resumable like any other;
4. then the next link.

**Human checks.** If the page shows a captcha, a password field, a "verify you are human" check, or never gives a download after its timer, the NeoDM browser window comes to the front with "This site needs you. Solve the check in this window, then NeoDM continues by itself." The list window offers "Show the window" and "Skip this link". NeoDM waits (up to 10 minutes per link) and continues by itself when the page gives the download. If no download control can be recognised, NeoDM says so and waits for you to click the button yourself in that window; the download is still captured.

**Limits, plainly.** NeoDM never solves a captcha, never uses a solving service, never skips, shortens or speeds up a timer, never calls an address the page did not offer, and never reuses anyone else's links. It follows only the site of the link you pasted (and one hop to the host's own download address right after its own click); other sites and pop-ups are blocked. Each link has a budget of about 3 minutes plus the page's own timer (at most 15 minutes), and you can cancel. Host pages change: button detection can stop working for a host after a redesign, in which case the link ends as "needs you" and you click once. A form that answers a POST with the file itself (no redirect) cannot be fetched again by the download engine; hosts that redirect to the file after the POST work. Sign-ins and cookies stay in the NeoDM browser's private profile, which Options > Clear NeoDM browser data removes. Nothing about the pages or cookies is logged.

### Host pages (1.16.1)

Many file hosts answer a link with a page and not the file. NeoDM now tries the plain way first and keeps the NeoDM browser window (see above) for what it does not recognise.

**How the form resolver works.** For each page link, one at a time and in order: NeoDM asks for the page with ordinary web requests (browser-like headers, a cookie jar of its own for that link, your proxy settings, the host's usual Referer from a small table). It looks for the form of a free download (fields such as op, id, rand, referer, dl_token and a button like Free Download or Continue), waits the site's own timer in full (the seconds stated by the page, or the host's known minimum from the table; shown as "Waiting for the site's timer" with the seconds left, at most 120 seconds per step), posts the form as a browser would, reads the second step in the same way, and finds the direct link (a link in the answer, a value in a JSON answer, or a redirect to the file). The link is checked with a small request and handed to the download job with the Referer, cookies and user agent, so the engine downloads it like any other download. Some hosts draw the second step with a script and not a form; NeoDM reads the code, rand, token and countdown from that element. "Not allowed from domain" answers are retried once with the host's own address as Referer. Each link has about 3 minutes plus the site's timers.

**The captcha step is yours.** When the second step asks for a check (Google reCAPTCHA, hCaptcha or Cloudflare Turnstile), NeoDM opens a small page in your default browser, brings its own window forward and says "This site needs you. Click 'I'm not a robot' in your browser, then NeoDM continues by itself." You click once, in your browser; the page hands the answer back to NeoDM on this computer and NeoDM continues by itself with that link. The next link needs its own click. The panel has Open the page again, Skip this link and Cancel the rest; Close in the page links window also skips a link that is waiting for you.

**What NeoDM never does.** It never clicks, scripts or solves a captcha, never uses a solving service or a stored answer, never reuses an answer for a second file, never skips, shortens or speeds up a site's timer, never calls an address the page did not offer, and never follows another site than the one you pasted (except the host's own download address at the end).

**Limits.** Hosts change their pages; when the form is not recognised, or the post does not give a link, the link goes to the NeoDM browser window (with Back, Forward, Reload, Stop, Open in your browser, Copy address and Close) and you finish there or open it in your own browser. Image captchas, invisible score checks and other checks the browser step cannot carry also use the NeoDM browser window. A host whose captcha key only works on its own address (the pilot host's does: its check does not load on the local page) is always done in the NeoDM browser window. If the browser step cannot start (no default browser), use Open in your browser on the page link. A direct link that the site only gives once, or that is bound to the page's session, is downloaded with the same cookies and Referer, but a host may still refuse it.

### Clipboard watching

Options > Downloads > Link grabber, off by default. When on, copying text with two or more web links opens the grabber. The watcher looks at the clipboard only when Windows reports a change, ignores what was on the clipboard when it was switched on, ignores text NeoDM copied itself, reads at most 1,000,000 characters, offers the same text at most once a minute and any text at most once every four seconds, and sends nothing anywhere.

## Custom categories

Options > Save To > Custom categories. Each category has a name (60 characters at most, unique, not a built-in name), a folder, file extensions and address rules, and can be switched off.

- **Folder:** relative to the download folder, or a full path. Refused: `..`, reserved Windows names (CON, NUL, COM1, LPT1 ...), names ending in a dot or space, device paths (`\\?\`, `\\.\`), drive-relative or rooted paths, a bare drive, and any folder that passes through a link (junction or symbolic link).
- **Extensions:** comma separated, without dots or stars. `tar.gz` matches whole names ending in `.tar.gz`. Presets add the usual lists for documents, archives, audio, video, images, programs and e-books.
- **Address rules:** one per line. `example.com` matches that host and its subdomains; `*` and `?` work as wildcards (`*.example.com` also matches `example.com`); a rule with a slash such as `example.com/files/*` matches host and path of the address. A rule is checked against the address the job was added with (the final address once known) and the host of the referring page. No regular expressions are used.
- **Order:** a folder you pick yourself > your categories from the top of the list, all address rules first and then all extensions > the built-in categories (address rules, then extensions) > the download folder. A category whose folder is unsafe is skipped.
- **Built-in categories** (Programs, Compressed, Music, Video, Documents) keep their folder boxes. Their extensions, address rules and on/off switch can be edited too, but they cannot be deleted, renamed or moved. "Reset built-in" restores their defaults and leaves your categories alone.

The same rules decide the folder of normal downloads, streams, YouTube downloads, torrents, the capture dialog preview and the final saved path (also after the server settles the file name). Settings schema 9 adds `CustomCategories`, `BuiltInCategories` and `WatchClipboardForLinks`; the five folder settings of older versions are kept as they were.
